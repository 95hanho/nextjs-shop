# Troubleshooting

프로젝트를 진행하며 발생한 주요 문제와 해결 과정은 별도 문서로 정리했습니다.

## 1. Hydration 오류 해결

### 문제

Next.js SSR 환경에서 서버에서 렌더링된 HTML과 클라이언트 초기 렌더링 결과가 달라 Hydration 오류가 발생했습니다.

### 원인

- `<a>` 태그 내부에 다시 `<a>` 태그가 들어가는 잘못된 HTML 구조
- 클라이언트 상태에 따라 서버와 다른 UI가 렌더링됨
- hover 메뉴, 로그인 상태 등 클라이언트 의존 UI가 초기 렌더링에 영향을 줌

### 해결

- 중첩 anchor 구조 제거
- 클라이언트에서만 필요한 상태는 hydration 이후 반영
- 서버 렌더링과 클라이언트 초기 렌더링 구조를 동일하게 유지

### 결과

Hydration warning을 제거하고 초기 렌더링 안정성을 확보했습니다.

## 2. 토큰 재발급 중복 요청 문제

### 문제

Access Token 만료 시 여러 요청이 동시에 발생하면 Refresh Token 재발급 요청이 중복으로 실행되는 문제가 있었습니다.

### 원인

각 요청이 독립적으로 토큰 만료를 판단하고 refresh API를 호출했습니다.

### 해결

- middleware 인증 흐름 정리
- 사용자/판매자/관리자 토큰 처리 로직 분리
- 공통 refresh 유틸을 통해 중복 로직 감소

### 결과

불필요한 refresh 요청을 줄이고 로그인 유지 흐름을 안정화했습니다.

## 3. 상품 이미지 렌더링 처리

### 문제

상품 이미지가 CDN, 로컬 업로드 경로, 기본 이미지 등 다양한 형태로 들어와 Next.js Image 컴포넌트 사용 시 반복적인 예외 처리가 필요했습니다.

### 원인

이미지 경로 형태가 일정하지 않고, 상품 데이터에 이미지가 없는 경우도 존재했습니다.

### 해결

- `SmartImage` 공통 컴포넌트 생성
- 기본 이미지 fallback 처리
- `fill` / `width`, `height` 사용 방식을 타입으로 분리
- 상품 리스트에서는 첫 번째 이미지에만 priority 적용

### 결과

이미지 관련 반복 코드를 줄이고, 상품 리스트와 상세 화면의 이미지 렌더링 방식을 일관되게 관리할 수 있게 되었습니다.
