# Code Convention

프론트엔드 컴포넌트의 가독성과 유지보수성을 높이기 위해 작성 순서를 정리했습니다.

## React Component 작성 순서

```tsx
// 1) [store / custom hooks] -------------------------------------------
// 2) [useState / useRef] ----------------------------------------------
// 3) [useQuery / useMutation] -----------------------------------------
// 4) [derived values / useMemo] ---------------------------------------
// 4.5) [custom hooks] -------------------------------------------------
// 5) [handlers / useCallback] -----------------------------------------
// 6) [useEffect] ------------------------------------------------------
// 7) [UI helper values] -----------------------------------------------
// 8) [return] ---------------------------------------------------------
```

## 기준을 정한 이유

- 컴포넌트 내부 로직의 위치를 예측 가능하게 만들기 위해
- 상태, 서버 요청, 파생값, 이벤트 핸들러, 렌더링 영역을 분리하기 위해
- 컴포넌트가 길어져도 필요한 로직을 빠르게 찾기 위해
- 기능 추가 및 수정 시 코드 탐색 비용을 줄이기 위해
